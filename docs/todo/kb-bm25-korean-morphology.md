# TODO: KB 검색 bm25에 한국어 형태소 분석 적용 검토

> 상태: **미착수 · 검토** (2026-10-27 등록)

## 현황

- `kb_search`의 bm25 순위(`kbSearch: "bm25"`, 기본은 `keyword`)는 `tokens()`(`src/core/kb/framework-kb.ts`)로 토큰을 나눈다.
  - 영문: 식별자 전체 + camelCase 조각.
  - 한글: 공백·기호로 자른 어절 전체 + **2글자 조각(bigram)**. 예: `트랜잭션을` → 트랜잭션을, 트랜, 랜잭, 잭션, 션을.
- 사전 검색(prefetch)은 설정과 무관하게 항상 keyword다. 따라서 형태소 분석은 `kbSearch: "bm25"`일 때의 `kb_search`에만 영향을 준다.
- 측정 기록: `docs/reports/f-review-kb-search-bm25-20261021.md`. 질의 81개 대부분이 영문 식별자라서 한글 처리 품질은 따로 측정한 적이 없다.

## bigram 방식의 한계 (예상, 미측정)

- 조사·어미가 붙은 조각(`션을`, `서는`)이 토큰이 되어 무관한 페이지와 맞는다.
- 2글자 조각이 흔해서 IDF가 낮아진다. 그 결과 긴 한글 본문이 유리해진다.
- 복합명사(`계좌잔고조회`)를 `계좌`·`잔고`·`조회`로 나누지 못한다. bigram은 `좌잔`·`고조` 같은 경계 조각까지 만든다.

## 검토할 것

1. **필요성 먼저 측정**
   - 한글 질의 세트를 만든다. 리뷰어가 실제로 한글로 `kb_search`를 부른 기록, 그리고 KB 본문의 한글 설명 문장에서 뽑은 질의를 쓴다.
   - 그 세트에서 현재 bigram 방식의 hit@2와 MRR을 잰다.
   - 실제 호출 대부분이 영문이면 여기서 종료한다.
2. **선택지 (가벼운 순)**
   - a. 의존성 없이 조사·어미 접미사 제거: `을/를/이/가/은/는/의/에서/으로/하는/한다` 등. 그 뒤 bigram을 유지하거나 대체한다.
   - b. 사용자 사전(KB 용어집): KB 페이지 이름과 태그에서 한글 명사 목록을 만들어, 최장 일치로 복합명사를 나눈다.
   - c. 형태소 분석기 라이브러리: 순수 JS/WASM 후보를 조사한다.
3. **제약 확인**
   - 오프라인 설치 패키지(`scripts/offline/prepare.sh`): Bun 단일 번들, 5개 플랫폼, 망 분리 환경. 네이티브 바인딩(mecab-ko 등)은 플랫폼별 빌드가 필요하므로 사실상 제외한다.
   - 번들 크기와 초기화 시간: 사전이 수십 MB이면 부적합하다.
   - 라이선스.
4. **채택 기준**
   - 한글 질의 세트에서 hit@2가 개선되어야 한다.
   - 기존 81개 질의 결과가 나빠지면 안 된다(hit@2 29 이상).
   - `framework-kb.test.ts`가 통과해야 한다.
