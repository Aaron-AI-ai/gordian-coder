# 0.2.5 릴리스 노트

## 산출물 위치 통일 (f-review · f-log · fcq)

모든 산출물이 프로젝트의 `.fico/` 아래에 생기고, 실행마다 디렉터리가 하나씩 생깁니다.
이전 실행 결과는 옮기거나 덮어쓰지 않습니다.

```
.fico/report/f-review/report-<날짜>-<runId>/   review.md, review.html
.fico/report/f-log/report-<runId>/             log.md, log.html
.fico/report/fcq/report-<날짜-시각>/            report.json, index.html, result.md   (fcq 0.2.6)
.fico/f-review/runs/  .fico/f-review/manifest/  .fico/f-log/runs/                 작업 데이터
```

- f-review: 리포트(`fcq/report/f-review/`)와 작업 데이터(`fcq/f-review/`)가 `.fico/` 아래로 옮겨졌습니다.
  [기존] 표시용 이전 리포트는 새 위치에 하나도 없으면 예전 위치에서 읽습니다.
- fcq 0.2.6: 리포트 기본 위치가 `fcq/report/static`(덮어쓰기 + `static.<시각>` 백업)에서
  `.fico/report/fcq/report-<날짜-시각>/`로 바뀌었고, 설정은 `.fico/config/fcq.yaml`을 먼저 찾습니다
  (기존 `fcq/config/fcq.yaml`도 계속 읽음). f-review는 fcq 0.2.5도 그대로 지원합니다.
- `--output=파일.md`처럼 파일을 직접 지정하면 지금처럼 그 파일에 씁니다.
- 기존 `fcq/report/`, `fcq/f-review/`, `.fico/report/f-log/log-*.md`는 자동으로 옮기지 않습니다. 필요 없으면 지워도 됩니다.
- OpenCode는 `settings.gradle`이 있는 루트에서 실행하세요. 실행한 디렉터리 아래 `.fico/`에 결과가 생깁니다.

## 프로젝트 규칙 위치 (`rulesDir`)

- "이 프로젝트가 따라야 할 규칙" `.md`의 기본 위치가 `.fico/rules/`로 바뀌었고, f-review와 f-log가 함께 읽습니다.
- 위치를 바꾸려면 `fico_ai.json` **최상위**에 `"rulesDir": "<경로>"`를 둡니다(`review` 밖).
- 하위 호환: 기존 `review.rulesDir`·`log.rulesDir` 설정은 그 도구에서 계속 우선합니다. 아무것도 설정하지 않은
  프로젝트는 `.fico/rules`와 함께 예전 기본 위치(`review/rules`, `log/rules`)도 그대로 읽습니다.
- f-log용 조건(`exceptions:`, `handler:`)만 있는 규칙은 f-review에서 건너뜁니다.

## 업그레이드 안내 — AS-IS / TO-BE

기존 프로젝트는 아무것도 바꾸지 않아도 동작합니다(하위 호환). 아래는 새 구조로 맞출 때 **무엇을 어떻게 바꾸면 되는지**입니다.

### 1. 리포트·작업 데이터 위치

| 대상 | AS-IS | TO-BE |
|---|---|---|
| f-review 리포트 | `fcq/report/f-review/review-<label>.md` (폴더 하나에 계속 쌓임) | `.fico/report/f-review/report-<날짜>-<runId>/review.md` + `review.html` |
| f-review 작업 데이터 | `fcq/f-review/runs/`, `fcq/f-review/manifest/` | `.fico/f-review/runs/`, `.fico/f-review/manifest/` |
| f-log 리포트 | `.fico/report/f-log/log-<runId>.md` | `.fico/report/f-log/report-<runId>/log.md` + `log.html` |
| fcq 단독 실행 리포트 | `fcq/report/static/` (매번 덮어쓰고 이전 것은 `static.<시각>/`로 백업) | `.fico/report/fcq/report-<날짜-시각>/` (실행마다 새 디렉터리, fcq 0.2.6) |

**바꿀 것**
- 코드나 설정은 바꿀 필요가 없습니다. 새로 실행하면 TO-BE 위치에 생깁니다.
- 기존 결과 정리: `fcq/report/`, `fcq/f-review/`, `.fico/report/f-log/log-*.md`, `.fico/report/f-review.<시각>/`는 더 이상 쓰지 않으니 지워도 됩니다.
  (f-review의 [기존] 표시는 새 위치에 리포트가 하나도 없을 때만 `fcq/report/f-review/`를 읽습니다.)
- `.gitignore`에 산출물을 추가해 커밋되지 않게 합니다.
  ```
  .fico/report/
  .fico/f-review/
  .fico/f-log/
  ```
- OpenCode는 `settings.gradle`이 있는 **루트**에서 실행합니다. 서브 프로젝트에서 실행하면 그 아래 `.fico/`에 따로 생깁니다.

### 2. 설정 파일

| 대상 | AS-IS | TO-BE |
|---|---|---|
| fico ai 설정 | `fcq/config/.f-review.json` 또는 `.f-review.json` | `.fico/config/fico_ai.json` (예전 파일은 `fico_ai.json`이 없을 때만 읽음) |
| 프로젝트 규칙 설정 | `fico_ai.json`의 `review.rulesDir` (f-review만 사용) | `fico_ai.json` **최상위** `rulesDir` (f-review·f-log 공용) |
| 프로젝트 규칙 파일 | `review/rules/*.md`(기본) 또는 `fcq/rules/*.md` 등 직접 지정 | `.fico/rules/*.md` (기본) |
| fcq 설정 | `fcq/config/fcq.yaml` | `.fico/config/fcq.yaml` (fcq 0.2.6이 먼저 찾음, 예전 위치도 계속 읽음) |
| fcq 리포트 위치 설정 | `fcq.yaml`의 `report.output: fcq/report/static` | `report.output: .fico/report/fcq` (또는 줄 삭제 — 기본값) |

**바꿀 것** — `.fico/config/fico_ai.json`

AS-IS
```json
{
  "review": {
    "rulesDir": "fcq/rules",
    "language": "ko"
  }
}
```

TO-BE
```json
{
  "rulesDir": ".fico/rules",
  "review": {
    "language": "ko"
  }
}
```
- `review` 안의 `rulesDir`을 지우고 최상위로 옮깁니다. 기본값이 `.fico/rules`라서 `"rulesDir"` 줄을 아예 생략해도 됩니다.
- 규칙 파일을 옮깁니다: `fcq/rules/*.md`(또는 `review/rules/*.md`) → `.fico/rules/*.md`. f-log용 규칙(`log/rules/*.md`)도 같은 곳에 둡니다.
- 예전 `fcq/config/.f-review.json`은 `fico_ai.json`이 있으면 읽히지 않으므로 지워도 됩니다.

**바꿀 것** — fcq 설정
- `fcq/config/fcq.yaml` → `.fico/config/fcq.yaml`로 옮기고, `report.output` 값을 `.fico/report/fcq`로 바꾸거나 지웁니다.
- 주의: **fcq 0.2.5는 `.fico/config/`를 보지 않습니다.** 팀에 0.2.5 사용자가 남아 있으면 fcq 0.2.6을 배포할 때까지
  `fcq/config/fcq.yaml`에 사본을 남겨 두세요(0.2.6은 `.fico/config/`를 먼저 읽으므로 사본이 있어도 문제없습니다).

## f-review

- HTML 리포트 머리에 실행 명령, 설정, 소요 시간, 대상별 표를 보여 줍니다.
- **기존 코드의 의도를 지키는 수정안**: 수정 코드(TO-BE)가 기존 코드의 흐름을 바꾸지 않게 했습니다.
  예를 들어 `catch`에서 기본값으로 대체하던 처리(`catch → setOrdAbleQty(ZERO)`)를 예외를 던지는 코드
  (`throw PBOnlineException(...)`)로 바꾸면 업무 동작이 달라지므로, 작성자가 정한 처리 방식은 그대로 두고
  지적한 문제만 고치도록 리뷰 규칙과 지시문에 넣었습니다. 수정안이 `catch` 안에 `throw`를 새로 넣으면
  파일당 한 번 되돌려 보내 다시 확인하게 합니다.

## f-log 베타 오픈

에러 로그 분석 명령 `/f-log`를 **베타**로 공개합니다. Spring Boot(fico 프레임워크) 서비스의 Java 스택트레이스를
붙여넣거나 로그 파일을 지정하면, 원인 코드 위치 · 원인 · 해결 방안을 `.fico/report/f-log/report-<runId>/`에
리포트(`log.md`, `log.html`)로 만들어 줍니다. 근거는 저장소 코드, 사내 프레임워크 KB, 룰 파일만 씁니다(웹 검색 없음).

```
/f-log <스택트레이스 붙여넣기>
/f-log --file=logs/app.log
```

베타 기간에는 분석 결과가 틀릴 수 있으니, 리포트의 근거 파일과 수정 코드를 확인한 뒤 반영하세요.
사용법은 `docs/guides/04-f-log.md`를 보세요.

### 주요 기능

- **HTML 리포트**: f-review와 같은 형식의 `.html`을 `.md` 옆에 함께 만듭니다. 분석 대상(로그 파일·발생 시각·호스트/스레드·메시지·예외·기록 위치), 로그 분석, 원인, 해결 방안, 근거 자료(원인에 쓴 KB 페이지와 파일)를 보여 주고, 수정 코드는 복사 버튼으로 가져갈 수 있습니다.
- **프레임워크 KB 기반 수정안**: 용의 파일의 import와 로그 키워드로 KB 페이지를 미리 주입하고, 수정 코드가 쓰는 프레임워크 클래스의 KB 페이지와 대조합니다.
- **제출 검사 추가** (각 1회 반려)
  - 수정 코드가 바꾼 상수가 프레임워크 메서드 인자로 쓰이면, 그 호출과 KB 페이지를 보여 주고 허용 값인지 다시 확인하게 합니다 (예: `StringUtils.masking`의 마스킹 유형).
  - 수정한 설정 키가 KB의 `@ConfigurationProperties(prefix)` 밖에 있으면 실제로 바인딩되는 키를 알려 줍니다 (예: `cubeone.default-crypto-id` → `fico.crypto.cubeone.default-crypto-id`).
  - 리포트 문장에 섞인 한자를 막고, 수정안이 catch 폴백을 throw로 바꾸는 의도 변경을 막습니다.
- 같은 예외 블록 안의 반복 프레임을 묶어 세고, 관찰 항목 수를 제출 한도에 맞춥니다.
