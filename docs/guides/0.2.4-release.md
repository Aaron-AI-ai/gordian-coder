# 0.2.4 릴리스 노트

## 1. `--files`에 디렉터리 지정 지원 — 전체 프로젝트의 Java 파일 리뷰

`--files` 항목에 파일뿐 아니라 **디렉터리, `.`(프로젝트 전체), 글롭**을 쓸 수 있습니다.
추적 파일과 미추적 파일을 모두 포함하고 `.gitignore`는 존중합니다. `*`는 한 단계, `**`는 하위 전체입니다.
이전처럼 `git ls-files`로 파일 목록을 만들어 붙일 필요가 없습니다.

### 예시: on-stk-ord 프로젝트의 online 모듈 Java 코드 전체 리뷰

`on-stk-ord` 프로젝트 루트에서 `on-stk-ord-online` 모듈의 `src/main` 아래 Java 파일(약 55개)을 모두 리뷰합니다.

OpenCode TUI:

```
/f-review --files=on-stk-ord-online/src/main/**/*.java
```

터미널에서 바로 실행:

```bash
cd /Users/koscom/workspace/fico/on-stk-ord && opencode run --command f-review -- "--files=on-stk-ord-online/src/main/**/*.java"
```

디렉터리만 지정해도 되지만(`--files=on-stk-ord-online/src/main`), 이 경우 Java 외 파일(XML 등)도 대상에 포함됩니다.
Java만 리뷰하려면 위처럼 `**/*.java` 글롭을 쓰세요.

주의: 한 run에 최대 100파일입니다. online 모듈은 100개 이하라 한 번에 실행되지만, 프로젝트 전체(`--files=.`)처럼
100개를 넘으면 plan이 거부하고 범위를 좁히라고 안내하므로 모듈 또는 패키지 단위로 나눠 실행하세요.

## 2. 긴 파일을 나눈 구간(unit)의 병렬 처리

사용 방법은 바뀐 것이 없습니다. 달라진 것은 내부 처리뿐입니다.

- 이전: 길어서 구간으로 나뉜 파일은 구간을 **순차**로 리뷰했습니다.
- 이후: 구간(unit)마다 서브에이전트를 두어 **병렬**로 리뷰합니다.
  - plan 단계에서 구간을 미리 나누어 디스패치 목록으로 제공합니다.
  - 결과는 구간 단위로 저장되고, 최종 리포트에서 파일당 한 섹션으로 합쳐집니다.
  - 판정(judge)도 구간별로 자기 범위만 보고 채점합니다.
  - 구간별 리뷰가 파일 일부만 다루도록 커버리지 요약도 해당 구간으로 한정합니다.

## 3. 리포트: AI 지적과 fcq 지적 구분

리포트가 지적의 **출처**를 구분해 보여줍니다.

| 출처 | 의미 |
|---|---|
| `AI` | 리뷰어(AI)가 찾은 지적 |
| `fcq` | 정적 분석(fcq)이 찾은 위반 |
| `fcq+AI` | fcq 위반을 리뷰어가 같은 줄에서 후속 보고해 한 행으로 병합된 지적 |

- **마크다운**: 표의 마지막 열이 출처입니다.
- **HTML**:
  - 지적마다 출처 배지(`AI` / `fcq` / `fcq+AI`)가 붙습니다.
  - 툴바에 출처 필터(전체 / AI / fcq)가 심각도 필터 옆에 추가됐습니다. `fcq+AI` 행은 AI와 fcq 두 필터 모두에 나타납니다.
  - 파일 블록 안에서 `AI 리뷰` → 구분선 → `정적 분석` 순서로 묶입니다. AI 지적만 있는 파일에는 구분선이 없습니다.
  - 상단 요약의 지적 수가 출처별(AI n, fcq n)로 나뉘어 표시됩니다.
